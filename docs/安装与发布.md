# 可执行程序安装与发布

严谨程度：部署规范。发布包仅支持 Linux x86_64，内置官方 Node.js 26.11.1、后端依赖及前端资源。bubblewrap 和各 Agent CLI、登录凭据及 Agent 自身运行时由宿主机提供。

## 运行

发行版提供 `llm-compare --version`、`init --config <路径>`、`doctor --config <路径>`、`serve --config <路径>`。init 拒绝覆盖已有配置；doctor 检查配置、目录、bubblewrap、已有 Agent 程序及挂载路径，不发起模型请求。

新安装执行 init，配置默认为 `~/.config/llm-compare/config.yaml`；服务必须显式传入此路径。已有安装应复制现有配置并保留 data_dir、work_root，把 web_dist_dir 改为 embedded。数据与程序分开存储，替换可执行文件不会清除历史、附件或 Provider 凭据。

systemd 使用用户服务，以登录 Agent 的相同用户运行。Arch 包安装 `/usr/lib/systemd/user/llm-compare.service`，独立安装使用发布包内 install.sh。检查配置后执行：

```sh
llm-compare doctor --config ~/.config/llm-compare/config.yaml
systemctl --user enable --now llm-compare
systemctl --user status llm-compare
journalctl --user -u llm-compare -f
```

服务显式设置 HOME、USER 和基础 PATH。Agent 不在基础 PATH 时，以绝对路径登记 Agent，或在用户服务 override 中设置与实际安装一致的 PATH。服务保持本机回环访问。登录自动启动；需要未登录启动时，由管理员开启该用户 linger。

SIGTERM/SIGINT 停止调度、拒绝新写操作、取消对比和分析，并等待清理；超过取消确认时间加五秒后退出，未完成记录在下次启动时标记中断。升级前应先结束全部任务，停止服务，并备份 data_dir 和 work_root。SQLite WAL 模式下不得在服务运行时只复制主数据库。迁移已有自动备份；数据库不兼容时回退必须同时恢复数据库及对应附件，不能只降级程序。

## 构建与发布

构建依赖 Node.js 26、pnpm 11、curl 和 tar。`pnpm release` 执行 Lint、单元/集成测试、前端构建、后端打包、SEA 生成及发行版隔离验收；`pnpm release:build` 仅构建，`pnpm release:verify` 验证现有产物。

构建从 Node 官方下载固定版本及校验表，SHA256 匹配后生成 SEA，产物位于 dist/release，包含可执行文件、配置示例、服务单元、独立安装脚本、构建信息、第三方许可证及 SHA256SUMS。发布只上传 tar.gz 和校验文件，不上传本机配置、测试记录、数据、凭据及 Agent 登录文件。

版本来自根 package.json，提交来自构建时 Git HEAD。发布内容有未提交改动时构建直接失败。`pnpm release:publish` 校验产物提交等于已推送的 HEAD，创建 `v<版本>` 标签并发布 GitHub Release；标签或 Release 已存在时拒绝发布，变更发布内容必须递增版本。

下游版本检测依赖以下固定约定：标签为 `v` 加 package.json 中的 `X.Y.Z`；Release 为正式版且标记为 latest，不使用预发布；附件名为 `llm-compare-v<版本>-linux-x64.tar.gz` 和 `SHA256SUMS`。仓库公开，检测与下载无需令牌。nvchecker 可按如下方式配置：

```toml
[llm-compare-bin]
source = "github"
github = "yuuzao/llm-compare"
use_latest_release = true
prefix = "v"
```
